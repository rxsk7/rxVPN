# Разведка к этапам 3, 5, 6 (ноябрь 2026)

## WARP (этап 3)
- WireGuard в РФ ТСПУ распознаёт по рукопожатию (148 байт, не варьируется) и рвёт на всех крупных
  провайдерах с 2023 года; на ntc.party отмечают, что режется именно WireGuard на адреса WARP, а сами
  адреса доступны. Отдельные отчёты «у меня работает» — с провайдеров без ТСПУ.
- Вывод: WARP напрямую из РФ — ненадёжно. По умолчанию делать **WARP поверх своего сервера**
  (outbound wireguard в Xray с `sockopt.dialerProxy` = сервер): провайдер видит только VPS, Cloudflare — IP VPS.
  Напрямую — только опцией «попробовать», с проверкой.
- Регистрация как у wgcf: POST на API WARP с локально сгенерированным ключом x25519, из ответа —
  peer public key, адреса v4/v6 и `client_id` → 3 байта `reserved` для Xray.

## Белые списки (этап 5)
- Режим касается мобильного интернета (Минцифры, 21.03.2026): при ограничении открыт только
  согласованный список сервисов (госуслуги, банки, маркетплейсы, Яндекс…; >120 сервисов на март 2026).
- Обычный VPN в этом режиме не работает: закрыто всё, кроме разрешённых адресов, плюс DPI.
- Что проходило: серверы на «белых» российских IP (у хостеров из списка) и каскад «российский
  сервер на белом IP → зарубежный», с маскировкой под разрешённые ресурсы. В апреле 2026 РКН запретил
  облачным провайдерам сдавать такие IP под VPN, сервисы из списка давят за обслуживание VPN-пользователей —
  схемы живут недолго.
- Для rxvpn реально: (1) детектор режима — открываются 2–3 сайта из белого списка (gosuslugi.ru,
  ya.ru, vk.com) и не открываются 2–3 обычных (wikipedia.org, github.com) → «похоже на белые списки»;
  (2) переключение на сервер, помеченный «для белых списков» (каскад на российском белом IP, который
  человек добывает сам), с уведомлением. Сами обходы rxvpn не «изобретает».

## Tor на Arti (этап 6)
- Arti 2.4 (июнь 2026): клиент стабилен, есть доступ к .onion, мосты и pluggable transports
  (obfs4, Snowflake — внешними программами lyrebird / snowflake-client), relay — ещё нет.
  В 2.4 ломающие изменения API TorClient — привязываться к точной версии.
- План: arti-client внутри rxvpn, локальный SOCKS на 127.0.0.1 со случайным портом → outbound Xray
  `socks` с тегом `tor`; режимы «.onion» (domain regexp `\.onion$` → tor), «Сайт → Tor», «Всё через Tor»
  (только TCP, UDP → block). Соединение Arti к сети Tor — через SOCKS VPN (VPN → Tor); без VPN — мосты.
  Изоляция по сайтам — `IsolationToken` по хосту (Arti делает изоляцию по SOCKS-логину/паролю).
- Риски: размер exe (+~10–15 МБ), сборка под windows-gnu (arti тянет rusqlite — уже есть — и криптографию
  на чистом Rust), lyrebird/snowflake — отдельные .exe (Go), их хеши придётся пинить как ядро Xray.
